Coding guidelines

Also as you have seen, there is syntax which every programming language is very particular about. You will need to follow the syntax rules of the language in order to have your code run. In addition, there are some coding guidelines that will make your code more readable and easier to understand.

There are many wrong ways to get the right answer.

Read that again... Well written code is not just about getting the right answer, but also about writing code that is easy to read and understand and to reuse and maintain. The coding guidelines are intended to help you write code that is not only correct, but also well written and easy to read and understand.

One of my goals is to help you develop good coding habits that will help you to write better code.

Some of the common issues I saw in the first coding exercises were:

  • Missing or incorrect interpreter directive.
    In this first module, I do not reduce points for this, but check the example, and make sure to follow the explanations included in module 2. This is a common mistake which needs to be fixed early on. Your code might work within the IDE (IDLE) where you are working, but it will not work properly when called on another system. This needs to be included in all your Python files as specified in the instructions.
  • Missing mandatory header content.
    Make sure to include the required header content in all your Python files as specified in the instructions. Use the sample code as an example. At a minimum, the header will include your name, the date, and a brief description of the program and its purpose. This is important for readability and for grading.
  • Magic Numbers these are unnamed constants that appear in your code. Any number that appears in your code that is not clearly explained should be defined as a constant with a meaningful name. Constants should generally be defined at the top of your code, and should be in all uppercase letters with underscores to separate words. For example, instead of writing 3.14 in your code, you should define a constant like PI = 3.14. By doing this, your code is easier to understand, which also makes it less prone to errors and easier to maintain and reuse. If you need to change the value of the constant, you only need to change it in one place, rather than searching through your code to find all the instances of the number and changing them.
  • Not following the instructions and writing code that is not what was asked for. Read the instructions carefully and follow them closely. If you have any questions about the instructions, please ask for clarification in the online community or during office hours.
  • Another common issue, which wasn't really a problem in the first module, but will become more of an issue as we move forward, is indentation. Python uses indentation to define blocks of code. This means that the way you indent your code is very important. Be careful following the examples and make sure to use consistent indentation throughout your code. Most code editors will help with this automatically, but it is still important to be aware of it and to check your code for indentation errors. It is one of the most common errors in Python. It's one of those mistakes that we all make, so it's important to look out for it. More about this later.

Coding Logic and Design Patterns

The order of the course content is not accidental. In fact, if you look at just about any programming textbook or course curriculum, you will see a very similar order of topics. We start with sequential processing, the idea that each instruction follows the previous one, and then we move on to selection, which is the idea of making decisions in our code, and then we move on to repetition, which is the idea of doing something multiple times, and then move to other common topics such as modular code, exception handling, and object oriented programming. The order of these topics is not accidental, but is based on the idea of building on top of each other.

The more you code, the more mistakes you will see and the less scary they will become. Get familiar with the error messages and learn how to read them. They are not meant to be scary, but rather to help you understand what went wrong and how to fix it.
